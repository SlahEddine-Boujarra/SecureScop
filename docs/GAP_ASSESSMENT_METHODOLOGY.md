# Gap Assessment methodology

SecureScope assesses ISO/IEC 27001:2022 Annex A.8 technical controls using
explicit models and workspace-scoped evidence. Automated evidence supports an
analyst decision; it does not certify ISO compliance.

## Assessment models

- Quantitative coverage: current population, covered population and an
  approved versioned target.
- Checklist: required criteria keep Pass, Fail, Partial and Not assessed as
  qualitative results.
- Process capability: definition, ownership, repeatable operation and
  monitoring are evaluated separately.
- SLA: the full assessed sample is used, including overdue items.
- Effectiveness: successful testing still requires authorized validation.
- Evidence assurance: source, reference, freshness and expiration remain
  traceable.
- Risk-based: accepted risk requires owner, approver, scope, justification,
  residual risk, compensating controls and expiration.
- Composite: one unassessed required objective cannot be hidden by stronger
  results in another objective.

## Assurance dimensions

The detail view keeps these independent dimensions visible: Design adequacy,
Implementation, Scope coverage, Operating effectiveness, Evidence assurance
and Validation. Missing dimensions are reported as missing and are never
converted to zero.

## Workflow

1. Select or version a control profile.
2. Approve a measurable target when the model needs one.
3. Record evidence, criteria, tests and the six assurance dimensions.
4. Save the assessment. A gap is created when the result requires treatment.
5. Assign an improvement action, owner, due date, SLA and validation method.
6. Version the Statement of Applicability and Risk Treatment Plan.
7. Close only after evidence and authorized validation support the decision.

Every read and write uses the active `client_id`.
